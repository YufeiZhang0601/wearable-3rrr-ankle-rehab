# Wearable 3-RRR Ankle Rehabilitation Robot

URDF, kinematic model, and ROS 2 control demos for a wearable three-degree-of-freedom (3-DOF) ankle rehabilitation robot built on a 3-RRR spherical parallel mechanism (SPM). The device's remote center of rotation is co-located with the human talocrural / subtalar complex, enabling clinically meaningful pitch (dorsiflexion / plantarflexion), roll (inversion / eversion), and yaw (internal / external rotation) without parasitic shear loads.

The accompanying paper, *Design, Kinematic Optimization, and Assist-As-Needed Control of a Wearable 3-RRR Spherical Parallel Ankle Rehabilitation Robot*, is built from the LaTeX sources in [`report/`](report/).

A short demonstration of the closed-loop tracking running against the URDF model is available at [`media/closed_loop_demo.mp4`](media/closed_loop_demo.mp4) (≈ 25 MB).

## Quick start

### 1. Pure Python closed-loop demo (no ROS required)

```powershell
python scripts\ankle_rehab_closed_loop_demo.py
```

Parses `urdf/rh1.urdf`, treats `joint1`, `joint4`, `joint6` as the three Dynamixel XM430-W350-R virtual actuators, tracks a slow, low-amplitude rehab trajectory, and writes feedback to `demo_output/ankle_rehab_closed_loop.csv`. See [`docs/ankle_rehab_demo.md`](docs/ankle_rehab_demo.md) for arguments and safety notes.

### 2. One-shot inverse kinematics

```powershell
python scripts\parallel_ik_demo.py --roll-deg 5 --pitch-deg 10 --yaw-deg 0
```

Solves the parallel IK for one foot-plate orientation and prints the three motor angles. See [`docs/parallel_ik_derivation.md`](docs/parallel_ik_derivation.md) for the analytical and numerical formulations.

### 3. ROS 2 visualization

Place this repo in a ROS 2 workspace (tested with Humble) and build:

```bash
cd ~/ros2_ws/src && ln -s /path/to/wearable-3rrr-ankle-rehab rh1
cd ~/ros2_ws && colcon build --packages-select rh1
source install/setup.bash

ros2 launch rh1 display_robot.launch.py            # static URDF in RViz
ros2 launch rh1 ankle_rehab_demo.launch.py         # scripted rehab trajectory
ros2 launch rh1 parallel_ik_pose_demo.launch.py    # interactive pose → motor demo
ros2 launch rh1 gazebo.launch.py                   # Gazebo bring-up
```

See [`docs/parallel_ik_ros_demo.md`](docs/parallel_ik_ros_demo.md) for the interactive demo's topics, parameters, and how to wire it to a real Dynamixel bus.

## Hardware target

| Item             | Value                                                  |
| ---------------- | ------------------------------------------------------ |
| Active joints    | 3 × Dynamixel XM430-W350-R (RS-485 daisy chain)        |
| Master MCU       | Teensy 4.1 (1 kHz control loop)                        |
| Auxiliary sensors| dual IMUs (shank + foot), instrumented gait mat        |
| Position encoding| `tick = 2048 + θ_deg / 0.087912`, full range 0–4095   |

Inverse-kinematics joint angles `θ₁, θ₄, θ₆` are mapped to the three motor IDs.

## Design parameters

The mechanism geometry is parameterized by the link-length ratio
$\rho = L_2 / L_1$. Following the analysis in `docs/parallel_ik_derivation.md`, $\rho \approx 1.15$ pushes parallel singularities toward the boundary of the workspace and improves the global rotational-Jacobian isotropy by approximately 20 % relative to a naive 1:1 design. Concrete numerical parameters are in [`params/`](params/) and can be regenerated from a SolidWorks STEP export with:

```powershell
python scripts\extract_step_kinematics.py --step path\to\assembly.STEP
python scripts\auto_generate_parallel_ik_params.py
```
