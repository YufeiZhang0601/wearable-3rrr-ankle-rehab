# RH1 Parallel Ankle IK Derivation

This is the IK model used by `rh1/parallel_ik.py`. It is written for the
current project stage: three XM430-W350-R motors drive a 3-DOF spherical
parallel ankle mechanism, and the foot plate command is an orientation.

## Frames and Pose Command

Use a fixed base frame `{B}` and a neutral foot-plate frame `{F}`. The ankle
center is `C_B` in the base frame.

The desired foot plate orientation is:

```text
R_BF = Rz(yaw) * Ry(pitch) * Rx(roll)
```

where:

```text
pitch = dorsiflexion / plantarflexion
roll  = inversion / eversion
yaw   = internal / external rotation
```

For each leg `i`, define the foot-plate connection point in the neutral foot
frame:

```text
p_i^F
```

When the plate rotates, that point becomes:

```text
P_i^B = C_B + R_BF * p_i^F
```

## Actuator-Side Point

For each active motor axis:

```text
B_i^B = one point on the motor axis
u_i^B = unit direction of the motor axis
```

Define one actuator-side horn/rocker point at motor zero:

```text
A_i0^B
```

When the motor angle is `q_i`, that point rotates around the motor axis:

```text
A_i^B(q_i) = B_i^B + Rot(u_i^B, q_i - q_i0) * (A_i0^B - B_i^B)
```

`Rot(u, q)` is Rodrigues rotation around axis `u`.

## Constraint Equation

Each leg is modeled as an effective rigid link of length `L_i` between the
actuator-side point and the foot-plate point:

```text
|| P_i^B - A_i^B(q_i) || = L_i
```

So the scalar IK equation for each motor is:

```text
f_i(q_i) = || P_i^B - A_i^B(q_i) || - L_i = 0
```

The solver samples the allowed motor range, finds sign-change brackets, and
then uses bisection. If more than one root exists, it chooses the one closest to
the previous motor angle.

## What Parameters Are Still Needed

The STEP extraction already gives strong candidates for the three motor axes,
but a complete IK model still needs:

```text
A_i0^B: actuator-side horn/rocker point at zero angle
p_i^F: foot-plate connection point in foot frame
L_i: effective rigid link length
q_i0: motor zero offset relative to the CAD neutral pose
```

These can be confirmed from SolidWorks, or fitted from calibration data using
motor encoders plus Vive tracker foot-plate orientation.

## Control Pipeline

Once parameters are confirmed:

```text
desired roll/pitch/yaw
  -> ParallelAnkleIK.solve_orientation()
  -> q1/q4/q6 in radians
  -> Dynamixel goal ticks
  -> sync write to XM430-W350-R
  -> read back position/current/error
  -> Vive tracker and gait mat metrics
```

## Run the Solver

Use the synthetic smoke-test parameters to verify the command line:

```bash
python3 scripts/parallel_ik_demo.py params/parallel_ik_params.example.json
```

Use real RH1 geometry only after filling a confirmed parameter file:

```bash
python3 scripts/parallel_ik_demo.py params/parallel_ik_params.confirmed.json \
  --pitch-deg 8 \
  --roll-deg 4 \
  --yaw-deg 0
```

The fully automatic STEP bootstrap file is intentionally approximate. Use a
looser residual tolerance only for software bring-up:

```bash
python3 scripts/auto_generate_parallel_ik_params.py
python3 scripts/parallel_ik_demo.py params/parallel_ik_params.autogenerated.json \
  --pitch-deg 2 \
  --roll-deg 1 \
  --tolerance-mm 1.0
```
